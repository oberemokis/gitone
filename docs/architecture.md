# Архитектура

Один Go-модуль `gitone`, пакеты в `internal/`, точка входа в `cmd/gitone`. Документ описывает, как разложен код и какие правила не дают ему слипнуться. Граф зависимостей проверяет тест `architecture_test.go`, остальные правила держатся на ревью.

## Стек

- Go, версия модуля 1.27.
- Bubble Tea v2 (`charm.land/bubbletea/v2`): архитектура Elm (Model, Init, Update, View), ячеечный рендерер, клавиатура и мышь, понижение цвета под терминал.
- Lip Gloss v2 (`charm.land/lipgloss/v2`): стили и размещение блоков.
- gotreesitter (tree-sitter на чистом Go, без cgo): подсветка синтаксиса в `internal/syntax`. Набор грамматик задаёт `scripts/grammar-tags.sh`: теги `grammar_subset` и `grammar_subset_<язык>` для ста распространённых языков набора core100 без грамматик под копилефтом и vue, которого в core100 нет. `Makefile` кладёт их в `GOFLAGS`, рабочие процессы в `GITONE_TAGS` для `.goreleaser.yaml`. Пустой список роняет `make`, шаг рабочего процесса и хук `before` в `.goreleaser.yaml`: иначе сбой скрипта прошёл бы зелёным. Без тегов `go build` соберёт все двести, с GPL среди них. Решения в задачах #101 и #139.
- Один модуль с пакетами, а не несколько модулей. Отдельные `go.mod` ничего не дали бы: версионировать пакеты независимо никто не собирается.
- Задачи запускает `make`. Taskfile не взял: `task` не установлен, `make` есть.

## Пакеты

```
gitone/
├── cmd/gitone/            точка сборки: грузит дифф до интерфейса, запускает программу; команда update
├── internal/
│   ├── config/            JSON-файлы в структуры: форма, слияние со встроенными значениями
│   ├── keymap/            список действий и клавиш, клавиша в действие
│   ├── layout/            дерево раскладки и размер экрана в прямоугольники панелей
│   ├── git/               запуск git: дифф, индекс, коммит, лог, ветки, stash
│   ├── diff/              разбор unified diff, строки для видов split и unified
│   ├── syntax/            подсветка синтаксиса строк по имени файла, tree-sitter
│   ├── i18n/              словари интерфейса languages/*.json, текст на выбранном языке
│   └── tui/               корневая модель: заголовок, подвал, клавиши, окна
│       ├── diffview/      один файл диффа в виде split или unified, прокрутка
│       ├── picker/        выбор из списка с нечётким поиском, окно рисует корень
│       ├── theme/         цвета по ролям
│       ├── zone/          места клика мышью: невидимые метки в рисунке и их поиск
│       └── pane/files/    список изменённых файлов
├── architecture_test.go   проверка графа зависимостей
└── Makefile
```

Новый пакет появляется вместе с первым кодом, которому он нужен, и в тот же момент попадает в таблицу `architecture_test.go`.

## Граф зависимостей

```
cmd/gitone             → tui, config, keymap, layout, theme, i18n
tui                    → diffview, pane/files, picker, theme, zone, git, diff, config, keymap, layout, i18n
diffview               → diff, theme, syntax, i18n
pane/files             → theme, zone
theme, layout          → config, i18n
config, keymap, git    → i18n
syntax, diff, i18n     → ничего из проекта
picker, zone           → ничего из проекта
```

Стрелка разрешает импорт, всё, чего нет на схеме, запрещено. Панели не знают друг друга и не знают корня. Листья `config`, `git` и `diff` не знают ни терминала, ни друг друга.

Компилятор запрещает только циклы. Импорт сбоку, например `diff` в `git`, он пропустит, поэтому граф продублирован таблицей в `architecture_test.go`. Тест берёт импорты из `go list` и падает на любом запрещённом, а также на пакете, которого нет в таблице. Таблица видит только пакеты проекта, поэтому листьям `config`, `git` и `diff` тест отдельно запрещает импорт `charm.land/*` и `github.com/charmbracelet/*`. Новый пакет сначала получает место в графе, потом код.

## Правила

1. Ввод-вывод только в командах. `Update` и `View` не читают файлы и не зовут git. На часы `Update` смотрит в одном месте: клик в ту же клетку сразу после клика, закрывшего окно, отбрасывается (#150). Часы приходят в `Options.Now`, тест подставляет свои. Всё внешнее выполняется в `tea.Cmd` и возвращается сообщением. Поэтому любую модель можно проверить без терминала: сообщение на вход, состояние на выход.

2. Клавиша переводится в действие в одном месте. Корень спрашивает `keymap` и получает действие вроде `diff.toggleMode`, дальше работает только с ним: вызывает метод `diffview` или открывает окно. Панели клавиш не получают вовсе. Правка `keybinds.json` не трогает код. Окно забирает нажатия целиком и проверяет свои действия (`list.down`, `stash.apply`, `question.yes`) через `keymap.Is`, глобальные внутри окна не действуют. Зашит только `ctrl+c` (выход, в вопросе «нет») и `backspace` в полях ввода.

3. Панели не знают друг друга. Связи между ними держит корень: он хранит текущий файл, отдаёт его `diffview` и передаёт номер текущего панели файлов. Панели не импортируют ни друг друга, ни корень, это проверяет граф.

4. Панель не знает своего места. `diffview` и `pane/files` получают ширину и высоту и рисуют только содержимое. Положение на экране задаёт корень по раскладке, поэтому одна и та же панель работает в любой раскладке. Окна корень кладёт поверх панелей слоем.

5. Геометрия отдельно от отрисовки. `layout` превращает дерево раскладки и размер окна в прямоугольники и ничего не рисует. Это чистая функция, её проверяют таблицей размеров.

6. У состояния один владелец. Текущий файл, открытое окно и курсор списка хранит корень, вид, прокрутку и строки своего файла хранит `diffview`. Общих изменяемых структур и глобальных переменных нет. Значения уровня пакета есть только для чтения: регулярные выражения в `diff` и `layout` и встроенные словари `i18n`, которые разбираются один раз.

7. Объекты создаются только в `cmd/gitone`. Там читаются конфиги, открывается репозиторий и собирается корневая модель. Внутри `internal` нет `init()` с побочными эффектами и нет синглтонов.

8. Интерфейс объявляет тот, кто его использует, и только когда реализаций больше одной. Сейчас интерфейсов нет: корень вызывает `diffview`, `pane/files` и `picker` напрямую, у каждого своё устройство. Для git интерфейса нет: тесты работают с настоящим git во временном каталоге.

9. Смысл проверяет тот, кто его знает. `config` проверяет форму JSON: типы, обязательные поля, неизвестные ключи. Существует ли действие, есть ли такая панель, нет ли конфликта клавиш, проверяют `keymap` и `layout`. Иначе `config` пришлось бы знать о панелях и действиях интерфейса.

10. В коде нет текстов интерфейса, только ключи словаря. Тексты лежат в `internal/i18n/languages/<язык>.json`: английский полный, у другого языка тот же набор ключей, а строки, которой в нём нет, берётся из английского. Подстановки именованные (`{file}`). Клавиши в тексты не вписываются: вопрос получает клавишу ответа подстановкой `{yes}`, а подсказка окна собирается из клавиш keymap и подписей `action.<действие>.hint`, так перевод не разойдётся с кодом. Словарь выбранного языка передаётся явно, через `tui.Options`, глобального языка нет. Новый язык это новый файл словаря. Подписи действий keymap берутся по ключам `action.<действие>.footer` и `action.<действие>.help`, заголовки групп справки по `category.<категория>`.

    Ошибки нашего кода создаются через `i18n.New(ключ, подстановки)` и сами по себе английские. Текст на выбранном языке собирают tui и cmd при показе (`Dictionary.Error`): язык становится известен только после чтения `config.json`, а ошибки этого файла появляются раньше. Обёртка вида `fmt.Errorf("%s: %w")` с именем файла, путём или операцией git остаётся префиксом, внутренняя ошибка переводится. Ошибки git, `encoding/json` и `os` идут как есть.

## Как проходит событие

Пример: нажали `]`, следующий файл.

1. Bubble Tea присылает корню `tea.KeyPressMsg`.
2. Корень смотрит, открыто ли окно. Открытое окно забирает нажатие целиком. Окна нет, и корень спрашивает `keymap`: `]` означает `files.next`.
3. Корень сдвигает текущий файл и отдаёт его `diffview` методом `SetFile`. `diffview` пересчитывает строки.
4. `View` корня считает прямоугольники через `layout`, рисует панели (`pane/files` получает подписи и номер текущего, `diffview` свой файл) и кладёт сверху открытое окно.

Всё, что ходит в git, идёт командой. По `r` или тику опроса корень возвращает `tea.Cmd`, который зовёт `git diff` и разбирает вывод пакетом `diff`. Результат приходит сообщением, корень ставит новый дифф. Ни на одном шаге панель не обращается к другой панели.

## Что уже в коде

Экран диффа в альтернативном буфере терминала, раскладка по образцу critique:

```

                      internal/tui/app.go +12 -3 (1/4)

 10   func New(files []diff.File) Model {      10   func New(files []diff.File) Model {
 11 -     return Model{}                        11 +     colors := theme.Dark()

 main  gitone            ⠋ loading                       q quit   ? help
```

`cmd/gitone` грузит дифф (`tui.Load`: `git.Diff` и `diff.Parse`) до запуска интерфейса. Ошибка git печатается в stderr с кодом выхода 1, интерфейс не стартует. Если git думает дольше 200 мс, в stderr выводится `Loading diff…`.

Корень (`internal/tui`) рисует заголовок с путём и `+N -M` (над ним и под ним пустая строка) и подвал (`chrome.go`), переводит клавиши в действия через `keymap` и вызывает методы вида. Файлы показываются по одному: `]` и `[` открывают соседний и стоят на краях списка, `ctrl p` открывает окно поиска. Счётчик `(2/5)` стоит в заголовке. У краёв заголовка стрелки `‹` и `›` (#120): клик по ним открывает соседний файл, как `[` и `]`, у края списка стрелка приглушена. Длинное имя обрезается «…», стрелки и счётчики остаются на местах. Подвал, как и заголовок, окружён пустыми строками сверху и снизу (#103), и в нём три части (#83): слева ветка и имя каталога worktree (`git.Locate`, при detached HEAD короткий хэш), каждое со своей клавишей окна из keymap: «B main   W gitone» (#108), по центру спиннер загрузки или ошибка git, справа подсказки клавиш с флагом «в подвал». Правый край главный, центр уходит левее, если не помещается, левый край обрезается первым. Ветка читается вместе с диффом при перечитывании и опросе. Без изменений раскладка та же: панель файлов и дифф пишут `No changes`, поиск открывается с надписью `No files` (#82).

`diffview` держит один файл: вид, размер, прокрутку и готовые строки. Строки пересчитываются при смене файла, вида или размера, а не в каждом `View`, а рисуются только видимые. Режим `auto` выбирает split от 120 колонок, `m` переключает от того вида, что на экране, и держит выбор до конца сеанса. При смене вида наверху остаётся та же строка файла по номеру: в split строк меньше, чем в unified. Длинная строка без переноса сдвигается вбок вместе со всем кодом файла (`shift`), с переносом режется на куски по ширине колонки; оба режима рисуют код с колонки `skip` (`wrap.go`). Полоса горизонтальной прокрутки забирает нижнюю строку панели, только когда есть что сдвигать. Таб становится четырьмя пробелами. Особые файлы показываются служебной строкой: `Binary or large file`, `mode 644 → 755`, `No content changes`, нераспознанный блок git текстом как есть.

Клавиши: `j`/`k` и стрелки по строке, `ctrl d`/`ctrl u` на полэкрана, `g`/`G` в начало и конец, колесо мыши по 3 строки, `m` вид, `?` справка, `q` выход. Колесо включает режим мыши, поэтому текст выделяется с `shift`. Решения в задаче #10.

Клавиши заданы одним списком в `internal/keymap`: действие, категория, клавиши и флаги «в подвал» и «в справку», тексты к ним лежат в словаре. `keybinds.json` переназначает клавиши действий и не добавляет новых. Update, подвал и справка читают один и тот же список, поэтому не расходятся. Leader-клавиша в первой версии не поддерживается, решение в задаче #14.

Цвета лежат в `internal/tui/theme` по ролям, имена полей совпадают с ключами тем из [config.md](config.md). Тема выбирается полем `theme` в `config.json`. Файл `themes/<имя>.json` накладывается поверх встроенной `dark`, ключи без значения берутся из неё. Решения в задаче #15.

Окна лежат поверх диффа слоями Lip Gloss, как в opencode, и дифф виден по краям. На узком экране окно ужимается, а не уходит за край. Окна это поиск файлов, поле темы коммита, лог, ветки, worktree, stash и два вопроса: отмена правок файла и удаление stash. Кому идут клавиши, решает одно поле корня `active` (`window.go`), поэтому открыто не больше одного окна. Списки лога, веток, worktree и stash рисует общий `list`, курсор у открытого списка один. Список приходит ответом git и открывается, только если за это время не открыли другое окно. Справка не окно, а флаг: клавиш она не забирает и видна под вопросом об отмене правок. Исключение одно: справка не выше тела, а что не поместилось, прокручивают `list.up`, `list.down` и колесо мыши (на терминале 80 на 24 так достижима группа «Diff»). Заголовок с подписью закрытия стоит на месте, а пока справка помещается целиком, `j`, `k` и колесо двигают дифф как без неё (#152). Клавиши окон берутся из keymap, конфликт ищется внутри окна; подсказку внизу окна собирает его код из привязок. Решения в задаче #63. Заголовок у всех окон один (`windowTitle`, #107): жирное название слева, клавиша закрытия с подписью `close` справа, под ним пустая строка; в нижней подсказке закрытия нет. В подсказках окон, подвале и справке клавиша идёт цветом текста, а подпись приглушённая (`keyHint`, #89).

`picker` это окно выбора из списка с нечётким поиском по подпоследовательности символов, без ранжирования, в порядке диффа. Это поле ввода, поэтому, пока оно открыто, корень отдаёт ему нажатия целиком: `q` и `?` набираются в поиск, `ctrl c` выходит всегда. Что делать с выбором, решает корень. Справа в списке стоит статус файла, если он не просто изменён: так различимы две записи с одним путём, например файл, ставший симлинком. Решения в задаче #11.

Пакет `diff` разбирает вывод `git diff` функцией `Parse` в файлы, хунки и строки. Хунк читается по счётчикам из `@@`, а не по префиксу строки. Пути берутся из `---`/`+++`, `rename`, `copy` и в последнюю очередь из заголовка `diff --git`. Управляющие символы содержимого заменяются видимыми значками, строки длиннее 4096 символов обрезаются с «…». Пути в `File` остаются сырыми, они нужны git, а на экран имя идёт через `diff.Printable`. Конец строки CRLF остаётся признаком `Line.CR`, значок `␍` рисуется только у пары, которая различается концом строки. То, что разбор не узнал (`diff --cc`, `--stat`, `* Unmerged path`), становится записью со статусом `raw` и текстом как есть. Решения и отвергнутые варианты в задаче #8.

Из разобранного файла `Unified` и `Split` строят строки двух видов, без ширины и цветов (#9). В split удалённые строки встают в пары с добавленными, которые идут за ними, лишние получают пустую половину напротив. Между хунками одна строка-разрыв без `@@`. За строкой без перевода в конце идёт строка-пометка на её стороне.

## Работа с git

Установленный `git` вызывается через `os/exec`, go-git не используется.

- Поведение совпадает с тем, что пользователь видит в терминале: его `~/.gitconfig`, хуки, атрибуты, подмодули.
- Вывод у git машинный и стабильный: `git diff` в unified-формате, дальше `git status --porcelain=v2 -z` и `git log` с заданным форматом.
- Флаги вызова отключают из конфига пользователя только то, что ломает разбор: внешний дифф, цвет, пути без префиксов, относительные пути. Чтение не берёт `index.lock` (`GIT_OPTIONAL_LOCKS=0`).

Минус: без установленного git приложение не работает. Для утилиты поверх git это нормальное условие.

`git.Diff(dir, args)` отдаёт текст диффа, разбирает его пакет `diff`. С аргументами они уходят в `git diff` как есть. Без аргументов это `git diff HEAD --` по временной копии индекса, в которую неотслеженные файлы добавлены через `add -N`: так они видны добавленными, переименование в рабочем дереве видно переименованием, а настоящий индекс не трогается. В репозитории без коммитов базой служит пустое дерево. Файлы больше 10 МБ git отдаёт бинарными. Решения и отвергнутые варианты в задаче #7.

Пути, которые `gitone` сам отдаёт git (`Stage`, `Unstage`, `Discard` и сборка копии индекса для диффа), идут с `GIT_LITERAL_PATHSPECS=1`: путь из диффа это имя файла, а не шаблон. Пути, которые пользователь пишет сам (`gitone -- 'src/*.go'`), остаются шаблонами. Есть ли путь в HEAD, решает `ls-tree`: он видит и подмодуль, у которого для `cat-file` нет объекта, и `Discard` подмодуля отказывает. `StagedPaths` не отдаёт неслитые пути, чтобы `space` на конфликте слияния ставил файл, а не сбрасывал его к HEAD. `Stage`, `Unstage` и `Discard` с пустым списком путей отказывают до вызова git. Решения в задаче #144.

Обновление данных: при запуске, по `r` и опросом, как в lazygit. Раз в 2 секунды и когда терминал получает фокус, корень в фоне читает тот же `git diff` и индекс (`live.go`). Опрос тихий: подвал не меняется, вопрос discard не закрывается, ошибка не показывается (её покажет `r`), а одинаковый дифф и опрос со старыми аргументами экран не трогают. Пока идёт опрос или перечитывание, второй не запускается. Слежение через fsnotify было до #81: в большом репозитории оно упиралось в лимит дескрипторов и не видело изменений, сделанных git из другого терминала.

## Конфигурация

Форматы файлов, порядок слияния и ошибки описаны в [config.md](config.md). Схемы JSON предложено генерировать из тех же Go-структур, которыми читаются файлы, тогда схема и код не разойдутся.

## Тесты

- `architecture_test.go`: граф зависимостей.
- `messages_test.go`: каждый ключ словаря, который код называет литералом (`Text("…")`, `i18n.New("…")`), и ключи статусов файлов есть в `en.json`; в коде вне тестов нет строковых литералов с кириллицей.
- Тесты пакетов лежат во внешнем пакете (`package diff_test`) и видят только экспорт. Исключение `i18n`: выбор языка и полнота словарей проверяются внутри пакета на своём каталоге, второго встроенного языка пока нет.
- Тексты экрана: в `tui` основной экран, справка, окна и служебные строки диффа рисуются на псевдословаре, где каждый текст взят в `⟦⟧`. Слово вне скобок значит строку, которую забыли провести через словарь.
- `tui`: настоящий репозиторий во временном каталоге, нажатия в `Update`, проверка экрана через `View()`. Хелперы лежат в `helpers_test.go`, команды выполняет `runAll` так же, как Bubble Tea: части пакета одновременно, ответы в порядке пакета.
- `diff`, `layout`, `syntax`, `tui/theme`: табличные тесты на значениях. `config` и `keymap` читают файлы из `t.TempDir()`.
- `git`: настоящий `git init` во временном каталоге, без подмен. Граница процесса здесь и есть граница пакета.
- Опрос в `tui`: тесты подают таймер с одним тиком (`oneTick`), без ожидания настоящих двух секунд.
- Сквозные сценарии: у Charm есть `teatest`, решим при первом таком тесте.

Команды: `make test` гоняет всё без кеша с `-race -shuffle=on` (флаги в `TESTFLAGS`), `make lint` запускает `go vet` и проверяет `gofmt`. Кеш выключен из-за `architecture_test.go`: кеш `go test` не знает, что вывод `go list` зависит от импортов других пакетов, и из кеша тест показывал «ok» при нарушенном графе.
