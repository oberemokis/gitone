# Архитектура

Один Go-модуль `gitone`, пакеты в `internal/`, точка входа в `cmd/gitone`. Документ описывает, как разложен код и какие правила не дают ему слипнуться. Граф зависимостей проверяет тест `architecture_test.go`, остальные правила держатся на ревью.

## Стек

- Go, версия модуля 1.27.
- Bubble Tea v2 (`charm.land/bubbletea/v2`): архитектура Elm (Model, Init, Update, View), ячеечный рендерер, клавиатура и мышь, понижение цвета под терминал.
- Lip Gloss v2 (`charm.land/lipgloss/v2`): стили и размещение блоков.
- Один модуль с пакетами, а не несколько модулей. Отдельные `go.mod` ничего не дали бы: версионировать пакеты независимо никто не собирается.
- Задачи запускает `make`. Taskfile не взял: `task` не установлен, `make` есть.

## Пакеты

```
gitone/
├── cmd/gitone/            точка сборки: грузит дифф до интерфейса, запускает программу
├── internal/
│   ├── config/            JSON-файлы в структуры: форма, слияние со встроенными значениями
│   ├── git/               запуск git, текст диффа
│   ├── diff/              разбор unified diff, строки для видов split и unified
│   └── tui/               корневая модель: заголовок, подвал, клавиши, справка
│       ├── diffview/      один файл диффа в виде split или unified, прокрутка
│       ├── picker/        окно выбора из списка с нечётким поиском
│       ├── theme/         цвета по ролям
│       ├── keymap/        клавиша и область фокуса в действие
│       ├── layout/        дерево раскладки и размер окна в прямоугольники панелей
│       └── pane/files/    список изменённых файлов
├── architecture_test.go   проверка графа зависимостей
└── Makefile
```

Сейчас существуют `cmd/gitone`, `config`, `git`, `diff`, `tui`, `tui/diffview`, `tui/picker` и `tui/theme`. Остальные пакеты появятся вместе с первым кодом, которому они нужны, и в тот же момент попадут в таблицу `architecture_test.go`.

## Граф зависимостей

```
cmd/gitone             → tui, config
tui                    → diffview, picker, theme, git, diff, config
diffview               → diff, theme
picker                 → theme
theme                  → ничего из проекта
config, git, diff      → ничего из проекта
```

Дальше добавятся: `tui → pane/*, keymap, layout`, `pane/* → keymap, theme, git, diff`, `keymap, layout, theme → config`.

Стрелка разрешает импорт, всё, чего нет на схеме, запрещено. Панели не знают друг друга и не знают корня. Листья `config`, `git` и `diff` не знают ни терминала, ни друг друга.

Компилятор запрещает только циклы. Импорт сбоку, например `diff` в `git`, он пропустит, поэтому граф продублирован таблицей в `architecture_test.go`. Тест берёт импорты из `go list` и падает на любом запрещённом, а также на пакете, которого нет в таблице. Новый пакет сначала получает место в графе, потом код.

## Правила

1. Ввод-вывод только в командах. `Update` и `View` не читают файлы, не зовут git и не смотрят на часы. Всё внешнее выполняется в `tea.Cmd` и возвращается сообщением. Поэтому любую модель можно проверить без терминала: сообщение на вход, состояние на выход.

2. Панели получают действия, а не клавиши. `keymap` переводит нажатие в действие вроде `diff.toggleMode` с учётом фокуса и leader-клавиши. Панель обрабатывает `diff.toggleMode` и не знает, какой клавишей его вызвали. Правка `keybinds.json` не трогает код панелей.

3. Панели не знают друг друга. Панель сообщает о событии своим типом сообщения, например `files.Selected`. Корень ловит его и решает, кому оно нужно, например передаёт панели диффа `diff.Show`. Все связи между панелями лежат в одном файле корня, `route.go`, и читаются целиком.

4. Панель не знает своего места. Она получает ширину и высоту в `View` и рисует только содержимое. Рамки, заголовки и положение на экране задаёт корень по раскладке. Поэтому одна и та же панель работает в любой раскладке.

5. Геометрия отдельно от отрисовки. `layout` превращает дерево раскладки и размер окна в прямоугольники и ничего не рисует. Это чистая функция, её проверяют таблицей размеров.

6. У состояния один владелец. Выбранный файл хранит панель файлов, панель диффа получает путь копией в сообщении. Общих изменяемых структур и глобальных переменных нет.

7. Объекты создаются только в `cmd/gitone`. Там читаются конфиги, открывается репозиторий и собирается корневая модель. Внутри `internal` нет `init()` с побочными эффектами и нет синглтонов.

8. Интерфейс объявляет тот, кто его использует, и только когда реализаций больше одной. Контракт панели живёт в `tui`, потому что панелей несколько. Для git интерфейса нет: тесты работают с настоящим git во временном каталоге.

9. Смысл проверяет тот, кто его знает. `config` проверяет форму JSON: типы, обязательные поля, неизвестные ключи. Существует ли действие, есть ли такая панель, нет ли конфликта клавиш, проверяют `keymap` и `layout`. Иначе `config` пришлось бы знать о панелях и действиях интерфейса.

Контракт панели:

```go
type Pane interface {
	Update(msg tea.Msg) (Pane, tea.Cmd)
	View(width, height int) string
}
```

## Как проходит событие

Пример: в панели файлов нажали `j`.

1. Bubble Tea присылает корню `tea.KeyPressMsg`.
2. Корень спрашивает `keymap` и получает ответ: в области `files` клавиша `j` означает `files.next`.
3. Корень отдаёт действие панели в фокусе. Панель файлов сдвигает выбор и возвращает команду с `files.Selected{Path}`.
4. Корень получает `files.Selected` и по `route.go` отправляет панели диффа `diff.Show{Path}`.
5. Панель диффа возвращает команду, которая зовёт `git diff` и разбирает вывод пакетом `diff`. Результат приходит сообщением, панель кладёт его в своё состояние.
6. `View` корня считает прямоугольники через `layout` и собирает экран из `View` панелей.

Ни на одном шаге панель не обращается к другой панели.

## Что уже в коде

Экран диффа в альтернативном буфере терминала, раскладка по образцу critique:

```
                          internal/tui/app.go +12-3

 10   func New(files []diff.File) Model {      10   func New(files []diff.File) Model {
 11 -     return Model{}                        11 +     colors := theme.Dark()

             q quit   ctrl p files   ? help
```

`cmd/gitone` грузит дифф (`tui.Load`: `git.Diff` и `diff.Parse`) до запуска интерфейса. Ошибка git печатается в stderr с кодом выхода 1, интерфейс не стартует. Если git думает дольше 200 мс, в stderr выводится `Loading diff…`.

Корень (`internal/tui`) рисует заголовок с путём и `+N-M` и подвал (`chrome.go`), переводит клавиши в действия (`keys.go`) и вызывает методы вида. Файлы показываются по одному: `]` и `[` открывают соседний и стоят на краях списка, `ctrl p` открывает окно поиска. В подвале счётчик `files (2/5)`. Без изменений по центру `No changes`.

`diffview` держит один файл: вид, размер, прокрутку и готовые строки. Строки пересчитываются при смене файла, вида или размера, а не в каждом `View`, а рисуются только видимые. Режим `auto` выбирает split от 120 колонок, `m` переключает от того вида, что на экране, и держит выбор до конца сеанса. При смене вида наверху остаётся та же строка файла по номеру: в split строк меньше, чем в unified. Длинная строка обрезается по краю колонки, таб становится четырьмя пробелами. Особые файлы показываются служебной строкой: `Binary or large file`, `mode 644 → 755`, `No content changes`, нераспознанный блок git текстом как есть.

Клавиши: `j`/`k` и стрелки по строке, `ctrl d`/`ctrl u` на полэкрана, `g`/`G` в начало и конец, колесо мыши по 3 строки, `m` вид, `?` справка, `q` выход. Колесо включает режим мыши, поэтому текст выделяется с `shift`. Решения в задаче #10.

Клавиши заданы одним списком в `internal/tui/keys.go`: клавиши, действие, категория, подпись в подвале, строка в справке. Update, подвал и справка читают его, поэтому не расходятся. Это зачаток `keymap`: список переедет туда, когда клавиши начнут читаться из `keybinds.json`.

Цвета лежат в `internal/tui/theme` по ролям, имена полей совпадают с ключами тем из [config.md](config.md). Пока тема одна и зашита в код (`theme.Dark`, пометка `ponytail:`), из `themes/*.json` она начнёт читаться в #15.

Окна справки и поиска файлов лежат поверх диффа слоями Lip Gloss, как в opencode, и дифф виден по краям. На узком экране окно ужимается, а не уходит за край.

`picker` это окно выбора из списка с нечётким поиском по подпоследовательности символов, без ранжирования, в порядке диффа. Это поле ввода, поэтому, пока оно открыто, корень отдаёт ему нажатия целиком: `q` и `?` набираются в поиск, `ctrl c` выходит всегда. Что делать с выбором, решает корень. Справа в списке стоит статус файла, если он не просто изменён: так различимы две записи с одним путём, например файл, ставший симлинком. Решения в задаче #11.

Пакет `diff` разбирает вывод `git diff` функцией `Parse` в файлы, хунки и строки. Хунк читается по счётчикам из `@@`, а не по префиксу строки. Пути берутся из `---`/`+++`, `rename`, `copy` и в последнюю очередь из заголовка `diff --git`. Управляющие символы содержимого заменяются видимыми значками, строки длиннее 1024 символов обрезаются. То, что разбор не узнал (`diff --cc`, `--stat`, `* Unmerged path`), становится записью со статусом `raw` и текстом как есть. Решения и отвергнутые варианты в задаче #8.

Из разобранного файла `Unified` и `Split` строят строки двух видов, без ширины и цветов (#9). В split удалённые строки встают в пары с добавленными, которые идут за ними, лишние получают пустую половину напротив. Между хунками одна строка-разрыв без `@@`. За строкой без перевода в конце идёт строка-пометка на её стороне.

## Работа с git

Установленный `git` вызывается через `os/exec`, go-git не используется.

- Поведение совпадает с тем, что пользователь видит в терминале: его `~/.gitconfig`, хуки, атрибуты, подмодули.
- Вывод у git машинный и стабильный: `git diff` в unified-формате, дальше `git status --porcelain=v2 -z` и `git log` с заданным форматом.
- Флаги вызова отключают из конфига пользователя только то, что ломает разбор: внешний дифф, цвет, пути без префиксов, относительные пути. Чтение не берёт `index.lock` (`GIT_OPTIONAL_LOCKS=0`).

Минус: без установленного git приложение не работает. Для утилиты поверх git это нормальное условие.

`git.Diff(dir, args)` отдаёт текст диффа, разбирает его пакет `diff`. С аргументами они уходят в `git diff` как есть. Без аргументов это `git diff HEAD --` по временной копии индекса, в которую неотслеженные файлы добавлены через `add -N`: так они видны добавленными, переименование в рабочем дереве видно переименованием, а настоящий индекс не трогается. В репозитории без коммитов базой служит пустое дерево. Файлы больше 10 МБ git отдаёт бинарными. Решения и отвергнутые варианты в задаче #7.

Обновление данных: при запуске и по явному действию. Слежение за файлами через fsnotify оставляем на потом.

## Конфигурация

Форматы файлов, порядок слияния и ошибки описаны в [config.md](config.md). Схемы JSON предложено генерировать из тех же Go-структур, которыми читаются файлы, тогда схема и код не разойдутся.

## Тесты

- `architecture_test.go`: граф зависимостей.
- `tui`: сообщения в `Update`, проверка состояния и `View()`. Уже есть тесты на центрирование и на клавиши выхода.
- `diff`, `config`, `keymap`, `layout`: табличные тесты без файловой системы, вход строка или байты.
- `git`: настоящий `git init` во временном каталоге (`t.TempDir()`), без подмены git. Граница процесса здесь и есть граница пакета.
- Сквозные сценарии: у Charm есть `teatest`, решим при первом таком тесте.

Команды: `make test` гоняет всё без кеша, `make lint` запускает `go vet` и проверяет `gofmt`. Кеш выключен из-за `architecture_test.go`: кеш `go test` не знает, что вывод `go list` зависит от импортов других пакетов, и из кеша тест показывал «ok» при нарушенном графе.
