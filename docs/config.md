# Конфигурация

Всё, что настраивает пользователь, лежит в JSON-файлах. Ни один файл не обязателен: без них работают встроенные значения.

Документ описывает предложение. Формат ключей взят у opencode ([клавиши](https://opencode.ai/docs/keybinds/), [темы](https://opencode.ai/docs/themes/)) с поправками под gitone. Имена полей в camelCase.

Сейчас читается из `config.json` только `diff.mode` и `diff.autoSplitMinWidth`, остальное появится с задачами, которые это используют. Неизвестное поле и неверный тип дают ошибку, которая стоит в подвале первой строкой, пока не нажата клавиша. Файл с ошибкой отбрасывается целиком. Решения в задаче #13.

## Где лежат файлы

```
~/.config/gitone/            или $XDG_CONFIG_HOME/gitone/
├── config.json              активные раскладка и тема, видимость элементов, режим диффа
├── keybinds.json            горячие клавиши
├── layouts/
│   └── compact.json         раскладка «compact», имя берётся из имени файла
└── themes/
    └── midnight.json        тема «midnight»
```

Порядок слияния: встроенные значения, затем пользовательский файл. Пользовательский файл переопределяет только те ключи, которые в нём есть. Раскладка или тема с именем встроенной заменяет её целиком.

Встроенные: раскладки `default` и `focus` (только дифф), тема `dark`.

## config.json

```json
{
  "$schema": "./schemas/config.schema.json",
  "layout": "default",
  "theme": "dark",
  "ui": {
    "statusBar": true,
    "keyHints": true,
    "paneTitles": true,
    "lineNumbers": true,
    "scrollbar": true
  },
  "diff": {
    "mode": "auto",
    "autoSplitMinWidth": 120
  }
}
```

Видимость скрывается на двух уровнях. Целая панель скрывается тем, что её нет в раскладке. Служебные элементы (строка статуса, подсказки клавиш, заголовки панелей, номера строк, полоса прокрутки) выключаются флагами в `ui`. Если нужен новый скрываемый элемент, он получает флаг, а не отдельный механизм. Сейчас работают `paneTitles`, `keyHints` и `lineNumbers`. Полосы прокрутки в коде пока нет, поэтому `scrollbar` и `statusBar` дают ошибку «неизвестное поле». Решения в задаче #16.

Поля `diff` описаны в [diff.md](diff.md).

## keybinds.json

Сейчас читаются переназначения действий и `none` или `false` для отключения. Поля `leader` и `leaderTimeout` и клавиши вида `<leader>…` дают ошибку, пока leader не сделан. Одна клавиша на двух действиях тоже ошибка. Решения в задаче #14.

```json
{
  "$schema": "./schemas/keybinds.schema.json",
  "leader": "ctrl+x",
  "leaderTimeout": 2000,
  "keybinds": {
    "app.quit": ["q", "ctrl+c"],
    "pane.next": "tab",
    "layout.next": "<leader>l",
    "layout.pick": "<leader>L",
    "diff.toggleMode": "m",
    "files.stage": "space",
    "files.discard": "none"
  }
}
```

Ключ в `keybinds` это идентификатор действия вида `область.действие`. Значение это одно сочетание, массив сочетаний или `"none"` (так же `false`) для отключения.

Сочетание пишется так, как его возвращает Bubble Tea: `ctrl+c`, `alt+enter`, `shift+tab`, одиночные клавиши `q` и `space`, имена `esc`, `up`, `pgdown`. Префикс `<leader>` означает нажатие leader-клавиши, затем второй клавиши в пределах `leaderTimeout` миллисекунд.

Область определяет, где действие работает. `app`, `pane` и `layout` глобальные. `files`, `diff` и остальные работают, когда в фокусе их панель. Одна клавиша в одной области на двух действиях это ошибка загрузки, сообщение называет оба действия.

Полный список действий живёт в коде и выводится командой приложения, в этот документ его не копируем: он разошёлся бы с кодом.

## layouts/*.json

Раскладка это дерево. Узел либо контейнер с направлением и детьми, либо лист с панелью.

```json
{
  "$schema": "../schemas/layout.schema.json",
  "root": {
    "direction": "row",
    "children": [
      { "pane": "files", "size": "30%" },
      {
        "direction": "column",
        "children": [
          { "pane": "diff" },
          { "pane": "commit", "size": 6 }
        ]
      }
    ]
  }
}
```

`direction` принимает `row` (дети слева направо) и `column` (сверху вниз). `size` это процент строкой (`"30%"`) или число ячеек. Узлы без `size` делят оставшееся место поровну.

Панели первой версии: `files` и `diff`. Следом по плану: `commit`, `log`, `branches`, `stash`. Сейчас работают встроенные `default` и `focus`, выбор имени идёт полем `layout` в `config.json`. Панель `files` без фокуса: клавиши переходов по файлам остаются прежними. На экране уже 80 колонок список файлов скрывается, остаётся один дифф. Переключения раскладки в работе нет, решения в задаче #17.

Проверки при загрузке: неизвестная панель, повтор одной панели, пустой `children`, сумма процентов больше ста. Ошибка называет файл и путь внутри него, например `layouts/compact.json: root.children[1].pane: неизвестная панель «branchs»`.

Переключение в работе: `layout.next` и `layout.prev` идут по списку, `layout.pick` открывает выбор по имени. Выбранное запоминается, где именно, см. вопрос 5 в [product.md](product.md).

## themes/*.json

Сейчас читаются ключи `textMuted`, `backgroundPanel`, `primary`, `accent`, `diffAdded`, `diffRemoved`, `diffAddedBg`, `diffRemovedBg`, `diffAddedWordBg`, `diffRemovedWordBg` и `error`. Ключ вне этого списка дает ошибку «пока не используется». Файл накладывается поверх `dark`, имя `dark` тоже. Решения в задаче #15.

```json
{
  "$schema": "../schemas/theme.schema.json",
  "defs": {
    "bg": "#0f1117",
    "fg": "#c9d1d9",
    "green": "#3fb950",
    "red": "#f85149"
  },
  "colors": {
    "background": "bg",
    "text": "fg",
    "textMuted": "#8b949e",
    "border": "#30363d",
    "borderActive": "#58a6ff",
    "diffAdded": "green",
    "diffAddedBg": "#12261e",
    "diffRemoved": "red",
    "diffRemovedBg": "#2d1214"
  }
}
```

Значение цвета: `#rrggbb`, число 0-255 для палитры ANSI, имя из `defs` или `"none"` (цвет терминала по умолчанию). Один файл описывает один вариант. Светлую тему пишем отдельным файлом, поэтому формат от opencode с парами `dark` и `light` в одном значении здесь упрощён.

Ключи цветов первой версии:

- основа: `background`, `backgroundPanel`, `text`, `textMuted`, `border`, `borderActive`, `primary`, `accent`
- состояния: `success`, `warning`, `error`, `info`
- статус файла: `statusAdded`, `statusModified`, `statusDeleted`, `statusRenamed`, `statusUntracked`, `statusConflict`
- дифф: `diffAdded`, `diffRemoved`, `diffContext`, `diffHunkHeader`, `diffLineNumber`, `diffAddedBg`, `diffRemovedBg`, `diffAddedWordBg`, `diffRemovedWordBg`

Ключи подсветки синтаксиса `syntaxKeyword`, `syntaxString`, `syntaxComment` и `syntaxNumber` читаются: язык файла определяется по имени, по содержимому не угадываем. Решения в задаче #19.

Ключ, которого нет в пользовательской теме, берётся из встроенной `dark`. Так пользователю достаточно перечислить только изменённые цвета. Цвета понижаются под возможности терминала автоматически, это делает Bubble Tea.

## Ошибки и проверка

Каждый файл читается отдельно, неизвестные поля считаются ошибкой (опечатка в ключе иначе молча ничего не делает). Файл с ошибкой заменяется встроенным значением, приложение запускается и показывает список проблем. Команда проверки без запуска интерфейса завершается с ненулевым кодом, если ошибки есть, чтобы её можно было вызвать из скрипта.

## Схемы для редактора

Схемы JSON предложено генерировать из Go-структур, класть в `schemas/` и подключать через `$schema`. Редактор тогда подсказывает ключи и находит опечатки до запуска. Адрес для `$schema` решим, когда появится репозиторий на хостинге: сейчас в примерах стоят относительные пути.
