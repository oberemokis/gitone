# Конфигурация

Всё, что настраивает пользователь, лежит в JSON-файлах. Ни один файл не обязателен: без них работают встроенные значения.

Формат ключей взят у opencode ([клавиши](https://opencode.ai/docs/keybinds/), [темы](https://opencode.ai/docs/themes/)) с поправками под gitone. Имена полей в camelCase. Примеры ниже содержат только то, что читается сейчас, а то, что ещё в плане, названо планом в тексте.

Неизвестное поле и неверный тип дают ошибку, которая стоит в подвале первой строкой, пока не нажата клавиша. Файл с ошибкой отбрасывается целиком. Решения в задаче #13.

## Где лежат файлы

```
~/.config/gitone/            или $XDG_CONFIG_HOME/gitone/
├── config.json              язык, активные раскладка и тема, видимость элементов, режим диффа
├── keybinds.json            горячие клавиши
├── layouts/
│   └── compact.json         раскладка «compact», имя берётся из имени файла
└── themes/
    └── midnight.json        тема «midnight»
```

Относительный `$XDG_CONFIG_HOME` (например, нераскрытая тильда `~/.config` или просто `cfg`) игнорируется, как велит спецификация XDG, и берётся `~/.config/gitone`: путь от текущего каталога указал бы на просматриваемый репозиторий. Имя темы и раскладки не бывает пустым, не содержит `/` и `\` и не начинается с точки, иначе файл не читается и появляется ошибка.

Порядок слияния: встроенные значения, затем пользовательский файл. Пользовательский файл переопределяет только те ключи, которые в нём есть. Раскладка с именем встроенной заменяет её целиком, а тема всегда накладывается поверх встроенной `dark`, в том числе из файла `dark.json`.

Встроенные: раскладки `default` и `focus` (только дифф), тема `dark`.

## config.json

```json
{
  "$schema": "./schemas/config.schema.json",
  "language": "en",
  "layout": "default",
  "theme": "dark",
  "ui": {
    "keyHints": true,
    "paneTitles": true,
    "lineNumbers": true,
    "autoReload": true
  },
  "diff": {
    "mode": "auto",
    "autoSplitMinWidth": 120,
    "wrap": true
  }
}
```

Видимость скрывается на двух уровнях. Целая панель скрывается тем, что её нет в раскладке. Служебные элементы выключаются флагами в `ui`. Если нужен новый скрываемый элемент, он получает флаг, а не отдельный механизм. Работают `paneTitles`, `keyHints`, `lineNumbers` и `autoReload`: последний включает автообновление диффа опросом раз в две секунды, по умолчанию включён. Решения по нему в задаче #81. Строки статуса в коде пока нет, поэтому `statusBar` даёт ошибку `unknown field`. Полоса горизонтальной прокрутки есть ([diff.md](diff.md)), но флага у неё нет: она появляется сама, когда есть что сдвигать, поэтому `scrollbar` тоже даёт `unknown field`. Решения в задаче #16.

Поля `diff` описаны в [diff.md](diff.md).

`language` задаёт язык интерфейса: подсказок, окон, справки и наших сообщений об ошибках. Без поля берётся язык системы из `LC_ALL`, `LC_MESSAGES` и `LANG` (первая непустая, из `ru_RU.UTF-8` берётся `ru`), а если словаря для него нет, английский. Поле с языком, для которого словаря нет, даёт ошибку в подвале и английский интерфейс; остальные настройки файла при этом применяются. Сейчас встроен только английский словарь, `en`. Словари лежат в `internal/i18n/languages/` репозитория, новый язык добавляется файлом словаря. Решения в задаче #64.

git получает тот же язык через переменную `LANGUAGE`, и его сообщения в подвале тоже идут на нём. Это работает по возможности: при `LC_ALL=C` и у сборки git без переводов (например, у `/usr/bin/git` на macOS) git отвечает по-английски. Пути, имена операций git и сам вывод `git diff` не переводятся.

## keybinds.json

Читаются переназначения действий и `none` или `false` для отключения. Решения в задаче #14.

```json
{
  "$schema": "./schemas/keybinds.schema.json",
  "keybinds": {
    "app.quit": ["q", "ctrl+c"],
    "diff.toggleMode": "m",
    "files.stage": "space",
    "files.discard": "none"
  }
}
```

Ключ в `keybinds` это идентификатор действия вида `область.действие`. Значение это одно сочетание, массив сочетаний или `"none"` (так же `false`) для отключения. Переназначение заменяет клавиши действия целиком.

Сочетание пишется так, как его возвращает Bubble Tea: `ctrl+c`, `alt+enter`, `shift+tab`, одиночные клавиши `q` и `space`, имена `esc`, `up`, `pgdown`. Клавиша «+» пишется `+`, с модификатором `ctrl++`: в подвале и справке она видна как «+» и «ctrl +». Имена строчные, модификаторы идут в порядке `ctrl`, `alt`, `shift`, `meta`, `hyper`, `super`. Заглавная буква пишется заглавной: `B`, а не `shift+b`. Остальные имена те же, что у Bubble Tea: `enter`, `tab`, `backspace`, `delete`, `insert`, `home`, `end`, `pgup`, `f1`…`f63`.

Имя проверяется при загрузке: клавиша, которой Bubble Tea не пришлёт (`escape`, `Enter`, `pagedown`, `shift+b`, `" "`), даёт ошибку с именем действия и клавиши, а не молча не работает. `none` это значение целиком: внутри массива `["none"]` ошибка, отключает `"none"` или `[]`. Клавиша, повторённая внутри одного действия, считается один раз.

Фокуса панелей нет, поэтому глобальные действия работают на всём экране, а одна клавиша на двух из них это ошибка загрузки, сообщение называет оба действия.

Справка по `?` показывает подпись и клавиши, но не имя действия, а угаданное имя даёт `unknown action` и отбрасывает весь файл. Поэтому имена глобальных действий лежат в таблице. В справку не попадают `help.close` и отключённые действия, в таблице они есть.

| `prompt.submit`, `prompt.close` | `enter`, `esc` | поле ввода (имя ветки, сообщение stash): принять, вернуться в прежнее окно |

Конфиг, который сделал бы окно ловушкой или отнял буквы у поля ввода, не загружается:

- закрытие (`list.close`, `search.close`, `commit.close`, `listSearch.cancel`, `prompt.close`) нельзя отключить: без него из окна не выйти. `question.yes` тоже нельзя: без него не подтвердить discard, удаление ветки и stash, хотя любая другая клавиша в вопросе значит «нет»;
- действиям поиска, поля поиска в списке, поля ввода и коммита нельзя дать клавишу, которая набирает текст: букву, знак, `space` и они же с `shift+`. Подходят `ctrl+…`, `alt+…`, `enter`, `esc`, `tab`, стрелки, `f1`…;
- `ctrl+c` зашит: выход из приложения на главном экране и в окнах, а в вопросе ответ «нет». `backspace` в поиске, поле ввода и поле коммита стирает символ. Эти клавиши действиям окон не назначаются, а `ctrl+c` не достаётся и глобальным действиям, кроме `app.quit`;
- в описании коммита зашиты ещё стрелки, `home`, `end`, `delete` и `enter` (новая строка). Их `commit.field` не достаются.

В окне коммита два поля, тема и описание. `commit.field` переключает их, `commit.submit` коммитит из темы вместе с описанием, а `enter` в описании ставит новую строку. Отдельной клавиши подтверждения из описания нет: нажми `commit.field`, потом `commit.submit`. `commit.field` со значением `"none"` отключает переключение, и описание тогда недоступно.

`app.quit` отключается (`"none"`), если нужна своя клавиша выхода или не нужна никакая: `ctrl+c` выходит всё равно.

Подсказка внизу окна показывает текущие клавиши его действий, отключённое действие из неё пропадает.

В плане leader-клавиша: поля `leader` и `leaderTimeout` и сочетания вида `<leader>l`, где второе нажатие ждётся `leaderTimeout` миллисекунд. Пока leader не сделан, эти поля и сочетания дают ошибку.

Обе таблицы сверяет с `keymap.Default` тест `keybinds_docs_test.go` в корне репозитория: действие без строки и имя, которого нет в коде, роняют его.

## layouts/*.json

Раскладка это дерево. Узел либо контейнер с направлением и детьми, либо лист с панелью.

```json
{
  "$schema": "../schemas/layout.schema.json",
  "root": {
    "direction": "column",
    "children": [
      { "pane": "files", "size": 8 },
      { "pane": "diff" }
    ]
  }
}
```

`direction` принимает `row` (дети слева направо) и `column` (сверху вниз). `size` это процент строкой (`"30%"`) или число ячеек. Узлы без `size` делят оставшееся место поровну.

Панели: `files` и `diff`. Коммит, лог, ветки и stash сделаны окнами поверх диффа, а не панелями раскладки. Встроены `default` (список файлов слева на 20%, справа дифф) и `focus`, выбор имени идёт полем `layout` в `config.json`. Панель `files` без фокуса: клавиши переходов по файлам остаются прежними. При запуске панель файлов скрыта всегда, `f` (действие `files.toggle`) открывает и закрывает её на любой ширине экрана. Раскладка решает, где панель встанет; в раскладке без неё, как `focus`, панель открывается слева на 20%. Решения в задаче #84. Край панели тянется мышью за стык с диффом, рамки нет (#121): ширина держится до выхода из gitone и переживает `f`, конфиг не меняется. Панель не уже 12 колонок, дифф не уже 20 (#151): после сужения терминала вытянутая ширина урезается по экрану, а когда окно вернулось к прежнему размеру, панель снова получает её. На экране уже 32 колонок вытянутая ширина не действует и панель берёт ширину раскладки. Тянется панель слева или справа от диффа; над или под ним (своя раскладка с `direction: column`) не тянется.

Проверки при загрузке: неизвестная панель, повтор одной панели, пустой `children`, сумма процентов больше ста. Ошибка называет файл и путь внутри него, например `layouts/compact.json: root.children[1].pane: unknown pane "branchs", available: files, diff`. Так же называется узел при `size` неверного типа: `layouts/compact.json: root.children[1].size: a size must be a string or a number`.

Переключения раскладки в работе нет. В плане `layout.next` и `layout.prev` по списку и `layout.pick` с выбором по имени, решения в задаче #17.

## themes/*.json

Читаются ключи `textMuted`, `backgroundPanel`, `primary`, `accent`, `worktree`, `diffAdded`, `diffRemoved`, `diffAddedBg`, `diffRemovedBg`, `diffAddedNumberBg`, `diffRemovedNumberBg`, `diffAddedWordBg`, `diffRemovedWordBg`, `syntaxKeyword`, `syntaxString`, `syntaxComment`, `syntaxNumber`, `syntaxFunction`, `syntaxType`, `syntaxConstant`, `syntaxProperty`, `syntaxOperator`, `syntaxTag` и `error`. Цвета `syntax*` относятся к видам токенов tree-sitter (#101): функции и методы, типы, константы с встроенными и булевыми значениями, свойства и поля, операторы, теги разметки. `diffAddedNumberBg` и `diffRemovedNumberBg` это фон номера и знака у изменённой строки, светлее фона кода (#85). `worktree` красит имя каталога worktree в подвале и в окне worktree, по умолчанию жёлтый `#e5c07b`; ветка рядом идёт цветом `accent` (#194). Ключ вне этого списка дает ошибку. Файл накладывается поверх `dark`, имя `dark` тоже. Решения в задаче #15.

```json
{
  "$schema": "../schemas/theme.schema.json",
  "defs": {
    "panel": "#161b22",
    "green": "#3fb950",
    "red": "#f85149"
  },
  "colors": {
    "backgroundPanel": "panel",
    "textMuted": "#8b949e",
    "accent": "#58a6ff",
    "diffAdded": "green",
    "diffAddedBg": "#12261e",
    "diffRemoved": "red",
    "diffRemovedBg": "#2d1214"
  }
}
```

Значение цвета: `#rrggbb`, число 0-255 для палитры ANSI, имя из `defs` или `"none"` (цвет терминала по умолчанию). Один файл описывает один вариант. Светлую тему пишем отдельным файлом, поэтому формат от opencode с парами `dark` и `light` в одном значении здесь упрощён.

Полный набор ролей по плану. Из него сейчас читаются только перечисленные выше, остальные дают ошибку, пока их не использует код:

- основа: `background`, `backgroundPanel`, `text`, `textMuted`, `border`, `borderActive`, `primary`, `accent`, `worktree`
- состояния: `success`, `warning`, `error`, `info`
- статус файла: `statusAdded`, `statusModified`, `statusDeleted`, `statusRenamed`, `statusUntracked`, `statusConflict`
- дифф: `diffAdded`, `diffRemoved`, `diffContext`, `diffHunkHeader`, `diffLineNumber`, `diffAddedBg`, `diffRemovedBg`, `diffAddedNumberBg`, `diffRemovedNumberBg`, `diffAddedWordBg`, `diffRemovedWordBg`

Для ключей подсветки синтаксиса язык файла определяется по имени, по содержимому не угадываем. Решения в задаче #19.

Ключ, которого нет в пользовательской теме, берётся из встроенной `dark`. Так пользователю достаточно перечислить только изменённые цвета. Цвета понижаются под возможности терминала автоматически, это делает Bubble Tea.

## Ошибки и проверка

Каждый файл читается отдельно, неизвестные поля считаются ошибкой (опечатка в ключе иначе молча ничего не делает). Файл с ошибкой заменяется встроенным значением целиком, даже если рядом с ошибкой стоят верные ключи. Отсутствующий файл ошибкой не считается, а ссылка на отсутствующий файл или на отсутствующий каталог настроек (dotfiles через stow, перенесённый репозиторий) считается: настройки есть, но не читаются, и в подвале стоит имя файла. Так же читается `keybinds.json` (#178). Ссылка на существующий каталог без нужного файла остаётся отсутствием файла. Приложение запускается, а ошибки всех файлов стоят в подвале одной строкой через «; ». В плане команда проверки без запуска интерфейса, которая завершается с ненулевым кодом при ошибках, чтобы её можно было вызвать из скрипта.

## Схемы для редактора

Схемы JSON предложено генерировать из Go-структур, класть в `schemas/` и подключать через `$schema`. Редактор тогда подсказывает ключи и находит опечатки до запуска. Схем пока нет, поле `$schema` читается и ни на что не влияет. Адрес для него выберем вместе со схемами: сейчас в примерах стоят относительные пути.
