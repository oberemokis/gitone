# Продукт

gitone это терминальное приложение для работы с git. По внешнему виду и настройке оно ориентируется на [opencode](https://github.com/sst/opencode), по качеству просмотра диффов на [critique](https://github.com/remorses/critique).

Статус: проект в подготовке. Решено то, что отмечено «решено». Остальное предложение, которое можно менять до начала кода.

## Что берём из образцов

Critique показывает split на широком терминале и unified на узком, подсвечивает изменения внутри строки, ищет файлы нечётким поиском, даёт выбор темы и умеет выборочно стейджить хунки. Всё это есть в его README.

Opencode хранит горячие клавиши в JSON с leader-клавишей (по умолчанию `ctrl+x`), для одного действия принимает строку, массив или `"none"`. Темы там тоже JSON: блок `defs` с именованными цветами и блок `theme`, где ключи названы по роли (`text`, `border`, `diffAdded`). Формат конфигов gitone строится по этому образцу, подробности в [config.md](config.md).

## Цели

Решено:

- Горячие клавиши настраиваются через JSON, каждое действие переназначается и отключается.
- Раскладок может быть несколько, пользователь готовит свои и выбирает удобную.
- Ненужные элементы интерфейса скрываются через JSON.
- Тема настраивается через JSON. Встроена одна тёмная, пользователь меняет в ней любой цвет или пишет свою.
- Дифф показывается в двух видах: split (две колонки рядом) и один под другим.
- Код разложен по пакетам, зависимости между ними однонаправленные.
- Стек: Go и Bubble Tea v2, один модуль с пакетами в `internal/`. Причины в [architecture.md](architecture.md).

Предложение: приложение запускается без единого конфига, все файлы необязательны, а ошибка в одном файле не мешает запуску.

## Чего не делаем

Эти пункты в запросе не звучали, поэтому исключены, пока не вернёте их явно:

- AI-функции и агент, как в opencode.
- Выгрузка диффов в веб и общие ссылки, как `--web` в critique.
- Работа с pull request на GitHub.

## План

Предложение, порядок следует вашему «сначала монорепа, потом дифф».

1. Каркас и документы. Сделан: модуль, задачи `make`, архитектура с проверкой графа, первый экран с `hello world`.
2. Загрузка конфигов: клавиши, раскладки, темы, видимость. Проверка и понятные ошибки.
3. Просмотр диффа только для чтения: рабочее дерево, индекс, коммит, в обоих видах. См. [diff.md](diff.md).
4. Панель файлов со stage, unstage, discard и коммитом.
5. Лог, ветки, stash.

## Открытые вопросы

1. «Друг под другом» это unified (удалённые строки над добавленными в одной колонке)? Или другой вид, например старый файл целиком над новым? Сейчас в документах стоит unified.
2. Какие источники диффа нужны в первой версии: рабочее дерево, индекс, коммит, диапазон коммитов, stash? Сейчас предложены первые три.
3. Конфиги строгий JSON или JSON с комментариями? Стандартный `encoding/json` комментарии не принимает. Я бы разрешил комментарии, расширение файлов осталось бы `.json`.
4. Нужен ли конфиг уровня репозитория (каталог `.gitone/` в проекте) поверх пользовательского? Сейчас только пользовательский.
5. Где запоминать выбранные раскладку и тему между запусками: отдельный файл состояния или правка `config.json`? Я за отдельный файл, чтобы приложение не переписывало пользовательский конфиг.
6. Что делать раскладке на узком терминале: переключаться на запасную автоматически или оставлять выбор пользователю?
7. Имя модуля сейчас `gitone` без адреса репозитория. Когда появится remote, модуль придётся переименовать, это правка импортов.
